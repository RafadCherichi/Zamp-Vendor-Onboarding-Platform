# Hosting the evaluator demo for free

The public source repository is [RafadCherichi/Zamp-Vendor-Onboarding-Platform](https://github.com/RafadCherichi/Zamp-Vendor-Onboarding-Platform). The checked-in [`render.yaml`](../../render.yaml) describes one Render web service built from the root Dockerfile, using Render's free plan.

## What the Blueprint sets up

- One Docker web service in Render's Singapore region, following the `main` branch.
- The React screens and FastAPI endpoints served from the same public URL.
- `/api/health` as the host health check.
- SQLite and uploaded documents in `/tmp`, which is writable but temporary on the free service.
- Production mode, debug disabled, and a secret generated by Render rather than stored in this repository.
- Alembic migrations and safe seed-if-empty setup run when the service starts. If the database is cleared, the app rebuilds the baseline synthetic demo data.

## Publish

1. Sign in to Render and choose **New → Blueprint**.
2. Connect the GitHub account if asked, then select `RafadCherichi/Zamp-Vendor-Onboarding-Platform` and branch `main`.
3. Review the resources before syncing. The service must show the **Free** plan and **US$0**; this Blueprint does not create a disk. Stop if Render shows a paid plan or charge.
4. After the first deploy is live, open its `onrender.com` URL and check `/api/health` returns HTTP 200 with database and storage ready.
5. Run the clean vendor, bank conflict, simulated registry outage, document preview, and refresh journeys from the demo runbook before sharing the URL.

## Free plan behavior

The hosting plan costs **US$0**. Free web services spin down after 15 minutes without requests and may take about a minute to respond to the first visit while starting again. They cannot attach persistent disks, and local files are temporary. A restart, spin-down, or deploy can clear the SQLite database and uploaded documents. When the database is empty, startup recreates the baseline synthetic demo cases; changes made by evaluators and uploaded files may be lost. Keep the published demo synthetic and avoid promising that edits will persist.
