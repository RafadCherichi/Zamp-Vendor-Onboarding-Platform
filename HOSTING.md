# Hosting the evaluator demo

The public source repository is [RafadCherichi/Zamp-Vendor-Onboarding-Platform](https://github.com/RafadCherichi/Zamp-Vendor-Onboarding-Platform). The checked-in [`render.yaml`](render.yaml) describes a single Render web service built from the root Dockerfile.

## What the Blueprint sets up

- One always-on Docker web service in Render's Singapore region, following the `main` branch.
- The React screens and FastAPI endpoints served from the same public URL.
- `/api/health` as the host health check.
- A 1 GB persistent disk at `/var/data`, used by both SQLite and synthetic document uploads.
- Production mode, debug disabled, and a secret generated by Render rather than stored in this repository.
- Alembic migrations and safe seed-if-empty setup run when the service starts. Existing applications and files are not reseeded on restart.

## Publish

1. Sign in to Render and choose **New → Blueprint**.
2. Connect the GitHub account if asked, then select `RafadCherichi/Zamp-Vendor-Onboarding-Platform` and branch `main`.
3. Review the resources and displayed price before syncing the Blueprint. It creates a paid `0.5c-512mb` web service and a 1 GB disk.
4. After the first deploy is live, open its `onrender.com` URL and check `/api/health` returns HTTP 200 with database and storage ready.
5. Run the clean vendor, bank conflict, simulated registry outage, document preview, and refresh journeys from the demo runbook before sharing the URL.

## Cost and limits

Render's current listed price for the `0.5c-512mb` compute plan is **US$7/month**. Persistent disks are listed at **US$0.25 per GB per month**, so the specified 1 GB disk adds about **US$0.25/month**. Expected base cost is about **US$7.25/month**, before any applicable taxes or usage above included allowances. Confirm the price Render shows during Blueprint setup; only continue if that cost is acceptable.

Render's free web service is **US$0**, but it cannot use a persistent disk, may restart, and spins down after 15 minutes without requests. Its local SQLite database and uploaded files are not durable across restarts or deploys. This is suitable only for a disposable preview, not the prepared evaluator demo dataset.
